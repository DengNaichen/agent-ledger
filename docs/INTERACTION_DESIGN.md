# 导航、写入与恢复

## 导航与任务上下文

`shared.tsx` 用 History API 和 popstate 导航；详情路径是 `/issue/<identifier>`，Go 静态处理器提供直达路由回退。`App.tsx` 将筛选、视图和折叠状态保存在组件内存中，不持久化到 URL 或 localStorage；刷新不能承诺恢复这些选择。

Project、type、标签条件和搜索词参与 API 查询，搜索框按 Enter 才提交搜索词；状态筛选在列表数据中选择可见列。切换状态或 Project 筛选重置折叠，在详情页选择筛选会返回列表。创建弹窗沿用当前 Project 和状态；All issues 下使用 triage。创建成功后展开所在状态组；有具体标签筛选时重读列表，由筛选结果决定新 issue 是否显示。

## 写入完成点

列表/看板移动状态先乐观更新，失败恢复此前整个 issues 快照并展示错误；详情状态等待响应后更新。两处都不能把发出请求当作持久化完成。当前整列表回滚和未取消的异步加载可能受交错请求影响，不能宣称已解决旧响应覆盖新状态。

新建与编辑使用原生 dialog，打开后聚焦标题；保存期间禁用提交按钮，成功关闭，失败保留内容并显示 role=alert。关闭/取消没有未保存草稿保护，不能承诺关闭后可恢复。评论成功后追加响应并清空输入，失败保留文本，提交期间禁用按钮。

页面在窗口重新获得焦点时重新加载数据，未使用 WebSocket 推送；列表还会随路径、Project、type、标签条件和已提交的搜索词变化加载。列表只应用最新一次加载的响应，防止较早筛选响应覆盖较新结果；这不覆盖状态写入与加载之间的并发。详情首次加载失败可能仍显示 Loading 与全局错误，当前没有独立重试按钮。

## 标签操作

标签管理页为 `/labels`。名称、颜色、描述和归档状态在原生 dialog 中编辑；失败保留草稿，创建时提示相似名称。标签所属组创建后固定，组支持创建与改名。合并前展示关联转移及源 ID 删除的影响。

详情标签选择器支持搜索与原生 checkbox 键盘操作，逐次增量保存，保存期间禁用选择，等待服务端成功和详情重读后显示结果。批量添加/移除由原生 dialog 提交一次事务；组内添加自动替换，移除可以同时选择多个组内值。列表/看板展示前两个标签和 `+N`。标签筛选对话框使用显式 Apply/Clear；组选项匹配任意子标签，any/all/none 组合所选标签和组，unlabeled 不允许再选标签。标签筛选参与 API 查询，筛选与批量选择不跨刷新持久化。

## 修改时验证

涉及保存与刷新时，用浏览器检查成功、服务不可达、慢响应和连续操作后的页面与实际记录；重点查看失败是否丢失文本、旧响应是否覆盖新选择。不要把这些需要检查的情形写成已经自动通过的保证。

状态可通过原生 select 修改，拖动不是唯一入口。检查 Tab、Enter、Escape、对话框关闭后的焦点和浏览器前进后退；窄屏下检查内联属性仍可操作。视觉来源见 [设计系统](DESIGN_SYSTEM.md)，执行环境见 [开发](DEVELOPMENT.md)。
